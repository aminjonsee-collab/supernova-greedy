## Hintlar

- Oddiy satr saralash "30" ni "3" dan oldin qo'yadi — xato.
- a ni b dan oldin qo'yish qachon yaxshi? Ikkala birlashmani solishtiring.
- Hamma son 0 bo'lsa nima chiqadi?

## G'oya

Comparator: `(b + a).compareTo(a + b)` — `a + b` kattaroq bo'lsa, `a` oldin.

## Isbot

Qo'shni juftlik usuli: `a`, `b` qo'shni bo'lsa va `b + a > a + b`, ularni almashtirish butun sonni kattalashtiradi (qolgan qismlar joyida qoladi). Bu munosabat tranzitiv (satrni `a·10^|b| + b` son sifatida yozib ko'rsatiladi), demak saralash to'g'ri tartibni beradi.

## Yechim

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        int n = ni();
        String[] s = new String[n];
        for (int i = 0; i < n; i++) s[i] = next();
        Arrays.sort(s, (x, y) -> (y + x).compareTo(x + y));
        if (s[0].equals("0")) System.out.println("0");
        else System.out.println(String.join("", s));
    }
}
```

## Shart

n ta buyum, i-sining og'irligi `w[i]`, qiymati `v[i]`. Sumka sig'imi W. Buyumni **bo'lib** olish mumkin (bir qismini olsangiz, qiymati ham proporsional). Maksimal qiymat?

## Kirish va chiqish

n W (1 ≤ n ≤ 10^5, 1 ≤ W ≤ 10^9), keyin n qatorda `w v` (1 ≤ w, v ≤ 10^6). Javob 6 xona aniqlikda.

## Misollar

```input
3 50
10 60
20 100
30 120
```
```output
240.000000
```
```input
1 10
20 100
```
```output
50.000000
```

## Hintlar

- Bir birlik og'irlik eng qimmat bo'lgan buyum qaysi?
- Nisbatlarni kasrsiz solishtiring: `v1·w2` va `v2·w1`.
- Oxirgi buyum qisman olinadi.

## G'oya

`v/w` bo'yicha kamayish tartibida saralab, sig'im tugaguncha olamiz.

## Isbot

Optimal yechimda nisbati kichikroq buyumdan biror qism olingan, nisbati kattaroq buyum esa to'liq olinmagan bo'lsa — o'sha og'irlikni almashtirish qiymatni oshiradi. Demak optimal yechim — greedy.

## Yechim

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        int n = ni();
        long W = nl();
        long[][] it = new long[n][2];
        for (int i = 0; i < n; i++) { it[i][0] = nl(); it[i][1] = nl(); }
        Arrays.sort(it, (x, y) -> Long.compare(y[1] * x[0], x[1] * y[0]));
        double total = 0;
        long cap = W;
        for (long[] b : it) {
            if (cap == 0) break;
            long take = Math.min(cap, b[0]);
            total += (double) b[1] * take / b[0];
            cap -= take;
        }
        System.out.println(String.format(Locale.US, "%.6f", total));
    }
}
```

- Deadline bo'yicha yurib, kursni "qabul qiling".
- Vaqt oshib ketsa — qabul qilinganlardan qaysi birini chiqarish eng foydali?

## G'oya

Moore–Hodgson: deadline bo'yicha saralab, davomiyliklarni max-heap'da saqlaymiz; umumiy vaqt deadline'dan oshsa — eng uzunini chiqaramiz.

## Isbot

Tanlangan to'plam uchun EDD tartibi optimal (exchange). Har qadamdan keyin heap — shu deadline'gacha mumkin bo'lgan eng ko'p kurs va ular orasida umumiy vaqti eng kichigi. Eng uzunini chiqarish sonni saqlaydi va vaqtni maksimal qisqartiradi.

## Yechim

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        int n = ni();
        int[][] c = new int[n][2];
        for (int i = 0; i < n; i++) { c[i][0] = ni(); c[i][1] = ni(); }
        Arrays.sort(c, (x, y) -> Integer.compare(x[1], y[1]));
        PriorityQueue<Integer> pq = new PriorityQueue<>(Collections.reverseOrder());
        long time = 0;
        for (int[] it : c) {
            pq.add(it[0]);
            time += it[0];
            if (time > it[1]) time -= pq.poll();
        }
        System.out.println(pq.size());
    }
}
```

## Shart

n ta ish, har biri 1 birlik vaqt oladi. i-ishning deadline'i `d[i]` (shu vaqtgacha tugashi kerak, vaqt 1 dan boshlanadi) va foydasi `p[i]`. Bir vaqtda bitta ish. Bajariladigan ishlar soni va maksimal umumiy foydani chiqaring.

## Kirish va chiqish

n (1 ≤ n ≤ 10^5), keyin n qatorda `d p` (1 ≤ d ≤ n, 1 ≤ p ≤ 10^9). Ikki son: ishlar soni va foyda.

## Misollar

```input
4
4 20
1 10
1 40
1 30
```
```output
2 60
```
```input
5
2 100
1 19
2 27
1 25
1 15
```
```output
2 127
```

## Hintlar

- Deadline'i d bo'lgan ishlar orasidan ko'pi bilan d tasi d-vaqtgacha bajarilishi mumkin.
- Deadline bo'yicha yuring va qabul qilingan foydalarni heap'da saqlang.
- Heap o'lchami joriy deadline'dan oshsa — eng arzonini chiqaring.

## G'oya

Min-heap'dagi to'plam — har doim deadline'larga sig'adigan eng foydali to'plam.

## Isbot

Bu scheduling matroid: "deadline'larga sig'adigan ishlar to'plami" matroid tashkil qiladi, va matroidda greedy optimal. Heap usuli — shu greedy'ning deadline tartibida bajarilishi.

## Yechim

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        int n = ni();
        int[][] job = new int[n][2];
        for (int i = 0; i < n; i++) { job[i][0] = ni(); job[i][1] = ni(); }
        Arrays.sort(job, (x, y) -> Integer.compare(x[0], y[0]));
        PriorityQueue<Long> pq = new PriorityQueue<>();
        long sum = 0;
        for (int[] j : job) {
            pq.add((long) j[1]);
            sum += j[1];
            if (pq.size() > j[0]) sum -= pq.poll();
        }
        System.out.println(pq.size() + " " + sum);
    }
}
```

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        int n = ni();
        PriorityQueue<Long> pq = new PriorityQueue<>();
        for (int i = 0; i < n; i++) pq.add(nl());
        long cost = 0;
        while (pq.size() > 1) {
            long s = pq.poll() + pq.poll();
            cost += s;
            pq.add(s);
        }
        System.out.println(cost);
    }
}
```

## Shart

Boshlang'ich kapital w. n ta loyiha: i-sini boshlash uchun kapital kamida `c[i]` bo'lishi kerak va u `p[i]` sof foyda beradi (kapitalga qo'shiladi, `c[i]` sarflanmaydi). Ko'pi bilan k ta loyiha. Yakuniy maksimal kapital?

## Kirish va chiqish

Birinchi qatorda `n k w` (1 ≤ n, k ≤ 10^5, 0 ≤ w ≤ 10^9), ikkinchisida `p[1..n]`, uchinchisida `c[1..n]` (0 ≤ p, c ≤ 10^9). Yakuniy kapital.

## Misollar

```input
3 2 0
1 2 3
0 1 1
```
```output
4
```
```input
3 3 0
1 2 3
0 1 2
```
```output
6
```

## Hintlar

- Hozir qaysi loyihalarni boshlay olasiz?
- Ular orasidan qaysi birini tanlash hech qachon xato emas?
- Kapital faqat o'sadi — ochilgan loyihalar ochiq qoladi.

## G'oya

Kapital bo'yicha saralangan loyihalarni ko'rsatkich bilan max-heap'ga "ochamiz", har qadamda heap'dagi eng foydalini olamiz.

## Isbot

Har qadamda eng katta foydani olish keyingi qadamlarda ochiladigan loyihalar to'plamini maksimal kengaytiradi; foyda manfiy emas, demak boshqa tanlov hech qachon ko'proq kapital bermaydi (greedy stays ahead).

## Yechim

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        int n = ni(), k = ni();
        long w = nl();
        long[] p = new long[n], c = new long[n];
        for (int i = 0; i < n; i++) p[i] = nl();
        for (int i = 0; i < n; i++) c[i] = nl();
        Integer[] idx = new Integer[n];
        for (int i = 0; i < n; i++) idx[i] = i;
        Arrays.sort(idx, (x, y) -> Long.compare(c[x], c[y]));
        PriorityQueue<Long> pq = new PriorityQueue<>(Collections.reverseOrder());
        int ptr = 0;
        for (int step = 0; step < k; step++) {
            while (ptr < n && c[idx[ptr]] <= w) pq.add(p[idx[ptr++]]);
            if (pq.isEmpty()) break;
            w += pq.poll();
        }
        System.out.println(w);
    }
}
```

## Shart

Mashina 0 nuqtadan target nuqtaga boradi. Boshida `start` litr yoqilg'i bor, 1 birlik masofa 1 litr. Yo'lda n ta stansiya: `pos` nuqtada `fuel` litr (to'xtasangiz hammasini olasiz; bak cheksiz). Minimal to'xtashlar soni? Yetib bo'lmasa -1.

## Kirish va chiqish


```output
-1
```
```input
100 10 4
```

## Hintlar

- Qaysi stansiyada to'xtashni darhol hal qilish shart emas.
- O'tib ketgan stansiyalarni "zaxira" sifatida saqlang.
- Yoqilg'i yetmay qolsa — zaxiradagi eng kattasidan foydalaning.

## G'oya

Regret greedy: yetiladigan stansiyalarni max-heap'ga solamiz; keyingi nuqtaga yetolmasak — heap'dan eng katta yoqilg'ini olib, "o'sha yerda to'xtagan edim" deymiz.

## Isbot

k ta to'xtash bilan eng uzoqqa yetish uchun yetiladigan stansiyalardan eng katta k tasini tanlash kerak (exchange). Algoritm har to'xtashda aynan shuni qiladi, demak minimal k bilan target'ga yetadi.

## Yechim

```java
import java.util.*;
import java.io.*;

public class Main {
    @IO

    public static void main(String[] args) throws IOException {
        long target = nl(), start = nl();
        int n = ni();
        long[][] st = new long[n][2];
        for (int i = 0; i < n; i++) { st[i][0] = nl(); st[i][1] = nl(); }
        PriorityQueue<Long> pq = new PriorityQueue<>(Collections.reverseOrder());
        long reach = start;
        int stops = 0, i = 0;
        while (reach < target) {
            while (i < n && st[i][0] <= reach) pq.add(st[i++][1]);
            if (pq.isEmpty()) { stops = -1; break; }
            reach += pq.poll();
            stops++;
        }
        System.out.println(stops);
    }
}
```
